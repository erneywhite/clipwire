# Clipwire — общий буфер обмена для Windows, Linux и macOS

> Рабочий бриф проекта для Claude Code. Начальная архитектура ниже обсуждалась до исследования
> и частично пересмотрена: актуальные решения — в разделе «Решения» и в `docs/architecture.md`.
> Личные настройки автора лежат в `CLAUDE.local.md`, он не в репозитории.

## Правила проекта

- Издатель в метаданных и установщиках — «Erney White».
- После любых изменений в проекте обновлять README.
- Сервер должен разворачиваться через GUI-панели с Docker: готовый образ и compose,
  без ручной сборки и команд по SSH.

## Идея

Бесплатный аналог Paste / Universal Clipboard для **Windows, Linux и macOS**:
- копируешь на одной машине (Ctrl+C / Cmd+C), вставляешь на другой (Ctrl+V / Cmd+V);
- работает **не только с текстом, но и с файлами** (и картинками);
- синхронизация через свой сервер, а не через чужое облако.

## Шаг 0 — исследование

Прежде чем писать код, посмотреть существующие open-source решения: CrossPaste, ClipCascade,
KDE Connect и другие. Для каждого: жив ли проект, работает ли с файлами, работает ли вне
локалки через свой сервер, есть ли E2E-шифрование, чего не хватает. Результат —
`docs/research.md`.

## Исходная архитектура (до исследования)

**Компоненты:**
1. **Клиент-демон в трее** для каждой ОС: следит за буфером, отправляет изменения, получает чужие.
2. **Relay-сервер** (Docker): принимает и раздаёт зашифрованные блобы, хранит недавнюю историю.
3. Опционально **UI истории буфера** (поиск, закрепление элементов).

**Безопасность (обязательно):**
- **End-to-end шифрование.** В буфер постоянно попадают пароли и токены. Сервер видит только
  зашифрованные данные, ключ живёт только на устройствах.
- Добавление устройства через pairing (QR-код или код подтверждения).
- TTL для элементов на сервере, лимит размера, ручная очистка.
- Возможность исключить приложения: не синхронизировать буфер из менеджеров паролей и т.п.

**Файлы — главная сложность:**
- Представление файлов в буфере разное на каждой ОС:
  - Windows: `CF_HDROP` (+ `FileGroupDescriptor` / `FileContents` для «виртуальных» файлов);
  - macOS: file URL в `NSPasteboard`;
  - Linux: `text/uri-list`; X11 и Wayland ведут себя по-разному, Wayland особенно ограничен
    (на GNOME может понадобиться расширение или `wl-clipboard`).
- **Ленивая передача:** при копировании отправляются только метаданные (имя, размер, хэш).
  Сам файл скачивается при вставке или по запросу.
- Если нельзя «вставить по требованию», запасной вариант: скачивание в папку и подмена буфера
  на локальный путь.
- Ограничение по размеру и подтверждение для больших файлов.

**Защита от петель:** у каждого элемента есть ID и устройство-источник, чтобы полученный
элемент не отправлялся обратно.

## Решения

- Пишем своё. У аналогов (обзор в `docs/research.md`) берём идеи, код из AGPL/GPL-проектов
  не копируем.
- Стек: Rust + iroh. iroh даёт P2P с обходом NAT (в локалке устройства идут напрямую),
  шифрованный QUIC и `iroh-relay` для своего сервера. Офлайн-доставку и историю с TTL держит
  сам сервер рядом со встроенным relay. UI позже на Tauri. Rust выбран из-за низкоуровневой
  интеграции с буфером ОС (COM на Windows, NSPasteboard на macOS): на Go через cgo она хуже.
- Клиент и сервер должны легко разворачиваться другими людьми: сервер — один `docker compose`
  с готовым образом из GHCR, клиент — один установщик.
- Первые клиенты — Windows и macOS, Linux проверяется в виртуалке.
- Репозиторий публичный.
- Клиент — Tauri 2, фронтенд на Svelte 5. Движок синхронизации остаётся Rust-библиотекой
  (`clipwire-agent`), Tauri — оболочка. Интерфейс должен одинаково работать в WebView2,
  WebKit и WebKitGTK: эффекты вроде `backdrop-filter` и прозрачных окон только с запасным
  вариантом.
- История: локальная зашифрованная база на каждом устройстве, срок хранения в настройках
  (день … бесконечно), закреплённые элементы не удаляются. Сервер — транспорт и короткий
  почтовый ящик для офлайн-устройств.
- Окно вставки — не полка во всю ширину, а компактное окно у курсора мыши: прижимается к
  рабочей области монитора, размер задаётся в настройках, управляется мышью (двойной клик —
  вставить) и клавиатурой (стрелки, Enter, Shift+Enter без форматирования, набор текста —
  поиск, Esc). Перед показом запоминается активное окно, после выбора фокус возвращается
  и отправляется Ctrl+V / Cmd+V. На Wayland — запасной режим (по центру, только в буфер).
- Файлы: при копировании везде сразу появляется карточка с превью; файл до порога
  (по умолчанию 100 МБ, настраивается, есть «всегда») сразу заливается в хранилище
  зашифрованным. Крупнее — передаётся при вставке, пока источник в сети. При вставке
  iroh берёт файл напрямую с источника, если он доступен, иначе из хранилища.
  Скопированный файл-картинка (png, jpg, webp и т. п.) считается картинкой: миниатюра,
  предпросмотр и редактор работают и для него.
  Хранилище — диск сервера или S3-совместимое; ключи S3 только на сервере, клиенты
  получают presigned-ссылки.
- Интерфейс берёт идеи у платных аналогов (Paste), внешний вид свой.
- Оформление: три темы (Графит — тёмная утилита с янтарным акцентом, Onest + JetBrains Mono;
  Бумага — тёплая светлая с чернильно-синим, Golos Text + IBM Plex Mono; Сигнал — холодная
  с мятным, IBM Plex Sans + Plex Mono), у каждой светлый и тёмный вариант, режим «как в
  системе» по умолчанию. Шрифты лежат в сборке файлами.
- Окно вставки: список, а не карточки; в строке устройство-источник и мета моноширинным;
  подсказки клавиш внизу. Пробел открывает рядом окно предпросмотра (картинка целиком,
  длинный текст с прокруткой, карточка файла).
- Предпросмотр ссылок — только карточка из og:-тегов, только по пробелу, страница не
  исполняется. Похожие на одноразовые ссылки (token, code, otp, reset, magic, login…) не
  загружаются. Есть кнопка «Открыть в браузере» и переключатель в «Приватности».
- Без группы клиент работает локально: история и окно вставки на одном устройстве, сервер
  подключается позже. Для файлов в локальном режиме в истории хранить ссылку на файл, а не копию.
- Логотип: задание для генерации — `docs/brand/logo-brief.md`; выбранный вариант перерисовать
  в SVG. Превью репозитория собирать из логотипа и настоящих скриншотов.
- Установщик NSIS оформить в стиле бренда: иконка установщика, картинка сбоку на первом и
  последнем экране (164×314) и шапка (150×57) из знака и цветов темы «Графит».
