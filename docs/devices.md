# Устройства группы, смена ключа и сведения об источнике

Основа уже есть и без согласования не меняется:

- `crates/clipwire-core/src/device.rs`: `DeviceCard`, `GroupKey::seal_card` и
  `open_card` (подпись Ed25519 ключом устройства + шифрование ключом группы),
  `rekey_secret` и `rekey_public` (X25519 из ключа устройства через HKDF),
  `seal_rekey` и `open_rekey` (пакет нового ключа для одного устройства),
  `device_id`.
- `crates/clipwire-core/src/proto.rs`: `ClientMsg::PublishCard`,
  `ClientMsg::ListDevices`, `ClientMsg::Rekey { new_group, envelopes }`,
  `ServerMsg::Devices(Vec<DeviceEntry>)`, `ServerMsg::Rekeyed { envelope }`,
  `ServerMsg::Excluded`.
- `crates/clipwire-core/src/item.rs`: `Item.ext: Vec<Ext>` (метка + байты),
  трейт `ExtList`, метка `ext::SOURCE_APP` и `SourceApp`. Элементы без `ext`
  читаются (`decode_item` → `ItemV3`).

## Карточки устройств

- После входа в группу агент публикует свою карточку (`PublishCard`): имя из
  настроек, ОС, `rekey_public(device_key)`, время выпуска. При смене имени
  устройства — заново.
- Сервер хранит последнюю карточку каждого устройства группы (по `DeviceId`
  соединения, не по содержимому) и отдаёт список на `ListDevices`:
  `DeviceEntry { device, card, last_seen_ms, online }`. Карточку больше 4 КБ не
  принимает.
- Клиент открывает каждую карточку `open_card(device, card)`. Не открылась или
  нет карточки (старая версия) — устройство показывается как «неизвестное
  устройство» с отпечатком id и в смене ключа участвовать не может (ему нечем
  передать новый ключ).

## Смена ключа

Запускает пользователь на любом устройстве группы: «Удалить устройство» (смена
ключа без него) или «Сменить ключ группы» (все остаются).

1. Устройство R берёт список устройств, проверяет карточки, исключает
   удаляемое.
2. Создаёт новый ключ `K2`, входит в новую группу (`JoinWithToken` на том же
   сервере), публикует там свою карточку.
3. Для каждого остающегося устройства D (кроме себя) — `seal_rekey(K2, D,
   D.rekey_pub, old_group_id)`, отправляет `Rekey { new_group, envelopes }` в
   старую группу.
4. Сервер в той же транзакции: помечает старую группу «ключ сменён» (ссылка на
   новую, время), сохраняет пакеты по устройствам, удаляет элементы истории и
   файлы старой группы, подключённым к старой группе устройствам шлёт их
   `Rekeyed { envelope }` или `Excluded` и закрывает их соединения.
5. Устройство, входящее в старую группу позже, получает только свой
   `Rekeyed` или `Excluded` (по `DeviceId` соединения). Пакеты и запись о
   старой группе живут 30 дней, потом удаляются.
6. Получив `Rekeyed`, устройство делает `open_rekey(device_key, old, envelope)`,
   сохраняет новое состояние (тот же сервер, новый ключ), перезапускает движок,
   входит в новую группу, публикует карточку. Код приглашения меняется.
   `Excluded` — устройство переходит в локальный режим с сообщением «это
   устройство удалили из группы».
7. Повторный `Rekey` в группу, где ключ уже сменён, — отказ.

Свойства: исключённое устройство не получает новый ключ и теряет доступ к
серверу группы (старая группа больше ничего не отдаёт), к прямой передаче
(p2p-ключ выводится из ключа группы) и к файлам. Ранее полученное у него
остаётся, это не отменить. Локальная история на остальных устройствах не
трогается.

## Сервер

Код — `crates/clipwire-server/src/devices.rs` (обработка сообщений) и
`src/store/devices.rs` (база).

**База.** Таблица `cards (group_id, device_id, card, updated_ms)` — последняя
карточка устройства в группе. Таблица `rekeys (group_id, device_id, envelope)` —
пакеты нового ключа. В `groups` два столбца: `rotated_to` (id новой группы) и
`rotated_ms` (когда сменили ключ); у обычной группы они пустые. Всё удаляется
каскадом вместе с группой.

**`PublishCard`.** Карточка пишется под `DeviceId` соединения, содержимое сервер
не разбирает. Карточка больше 4096 байт — ответ `Error`, соединение не рвётся.
Ответа на успешную публикацию нет; соединение обрабатывает сообщения по порядку,
так что `ListDevices` после `PublishCard` уже видит новую карточку.

**`ListDevices` → `Devices`.** Все устройства группы из таблицы `devices`, по
возрастанию id: карточка (пустая, если не публиковалась), `last_seen_ms` —
время последнего входа в группу, `online` — есть ли у устройства открытое
соединение с этой группой.

**`Rekey { new_group, envelopes }`** в старой группе. Проверки:

- `new_group` есть на сервере, отличается от старой и сама не в режиме «ключ
  сменён»;
- отправитель уже вошёл в `new_group` (так нельзя увести участников в чужую
  группу);
- старая группа ещё не в режиме «ключ сменён»;
- пакеты только для устройств старой группы, без повторов, не больше числа её
  устройств, каждый не длиннее 512 байт.

Если всё в порядке, в одной транзакции группа помечается, пакеты сохраняются,
элементы, файлы и карточки старой группы удаляются. Файлы с диска убираются
следом в фоне, под тем же замком, что при отмене загрузки; ждущие `Get` получают
`Cancelled`.

Ответ отправителю: сервер закрывает поток без `Error` (чистый конец потока).
Отказ — `Error` с причиной, затем закрытие, как у любой ошибки. Пакет для себя
отправитель класть не обязан, но может: при повторном входе в старую группу
(например, если ответ потерялся) без пакета он получит `Excluded`, с пакетом —
свой `Rekeyed`. Агент, у которого новый ключ уже сохранён, на `Excluded` из
старой группы не реагирует.

Остальные соединения старой группы сервер будит (`Hub::kick`): каждое отправляет
своему устройству `Rekeyed { envelope }` или `Excluded` и закрывает поток.
Соединение, которое вошло в группу в момент смены ключа, после регистрации
проверяет режим группы ещё раз и закрывается так же.

**Вход в группу со сменённым ключом.** Сначала проверяется секрет: с чужим —
обычный отказ. С верным — вместо `Joined` и истории одно сообщение (`Rekeyed`
для `DeviceId` соединения или `Excluded`), затем закрытие. `Push`, `Backfill` и
файлы в такую группу не принимаются: элемент отбрасывается, загрузка файла
получает `BlobFail::Protocol("ключ группы сменён")`.

**Срок.** Группа со сменённым ключом не считается заброшенной (её не трогает
чистка групп, в которые 90 дней никто не входил), но через 30 дней после `rotated_ms` удаляется
вместе с пакетами в обычном цикле чистки. До этого она занимает место в пределе
`CLIPWIRE_MAX_GROUPS`.

## Клиент

Код — `crates/clipwire-agent/src/devices.rs` (карточка, разбор списка, кому
достаётся ключ, состояние на диске), движок — `src/sync.rs`, приложение —
`apps/desktop/src-tauri/src/devices.rs` и `apps/desktop/src/settings/Devices.svelte`.

**Карточка.** Движок после входа в группу (после истории) отправляет
`PublishCard` и сразу `ListDevices`. Ответ `Devices` подтверждает, что сервер
карточки знает. Если соединение рвётся в первые 10 секунд после карточки без
этого ответа, движок считает сервер старым и до перезапуска карточки не шлёт
(сервер до этой волны не разбирает `PublishCard` и закрывает соединение). Имя
в карточке обрезается до 100 символов. Смена имени в настройках перезапускает
сервис, поэтому карточка публикуется заново.

**Команды.** Интерфейс говорит с движком через `devices::Controller` (канал
`Control` в движок): `list_devices` и `rekey(remove)`. Пока нет связи, команды
сразу получают отказ «Нет связи с сервером». Команды Tauri: `devices_list`,
`device_remove(device_id)` (id — 64 hex), `group_rekey`. Две последние
возвращают новый код приглашения и отпечатки устройств без карточки, которым
ключ не достался.

**Смена ключа на этом устройстве** идёт внутри сессии движка: `ListDevices`,
проверка карточек и `plan_rekey` (себя удалить нельзя, удаляемое должно быть в
группе), новый ключ, вход в новую группу вторым соединением того же эндпоинта,
карточка там и `ListDevices` как подтверждение записи, пакеты `seal_rekey` для
всех остающихся с карточкой и для себя, `Rekey` в старой группе. Успех — сервер
закрыл поток. Дальше движок не подключается и ждёт, пока его снимут, а
приложение сохраняет ключ (`adopt_key`: тот же сервер и ключ устройства, курсор
остаётся, очередь загрузок и outbox удаляются, их файлы были в старой группе) и
перезапускает сервис.

**Приём.** `Rekeyed` (при входе вместо `Joined` или посреди сессии) движок
открывает `open_rekey` и отдаёт событие `Rekeyed { old, key }`; пакет, который
не открылся, равен исключению. Приложение делает `adopt_key` и перезапускает
сервис, интерфейс получает `clipwire://group-rekeyed`. `Excluded` → событие
`Excluded { old }`, приложение выходит из группы как при «Отключить» (история
остаётся) и шлёт `clipwire://group-excluded`. Оба шага сверяют `old` с группой
на диске: если там уже другая группа, событие игнорируется. Так `Excluded` из
старой группы не выбросит устройство, которое уже на новом ключе.

**Интерфейс.** В «Синхронизации» блок «Устройства группы»: имя (или
«Неизвестное устройство»), ОС, отпечаток, в сети ли и когда было последний
раз, у всех кроме своего — «Удалить». Кнопка «Сменить ключ группы». Перед
подтверждением показывается, что будет с удаляемым и с остальными, какие
неизвестные устройства ключ не получат и что код приглашения сменится.

## Приложение-источник

- При копировании на Windows — владелец буфера уже известен (exe). Имя для
  показа: `FileDescription` из ресурсов версии exe, если нет — имя файла без
  `.exe`. Иконка: 32×32 из exe (`SHGetFileInfo` или `ExtractIconEx`) → PNG,
  кэш по пути exe в памяти. Не получилось — без иконки.
- `SourceApp` кладётся в `Item.ext` (`ext::SOURCE_APP`) и в запись истории
  (`Entry` тоже получает `ext`, чтение старых записей — как в `history.rs`).
- В окне вставки: маленькая иконка и имя приложения в строке меты, поиск по
  имени приложения.
- Если источника нет (буфер без владельца) — ничего не показывать.
