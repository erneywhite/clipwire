# Хранение истории

Как устроена локальная история после переделки 0.3: память не растёт вместе с историей.
До неё `History::load_all` расшифровывал все записи при запуске и держал их в памяти целиком,
вместе с картинками и HTML. 35 тыс. записей из Paste — это 163 МБ, с картинками было бы
больше 4 ГБ.

## Цель

- В памяти нет ничего, что растёт с числом записей. Держится только страница окна вставки,
  открытый предпросмотр и маленький кэш значков программ.
- Каждая запись по-прежнему зашифрована ключом истории (`history.key`). Открыто на диске лежит
  ровно то же, что и раньше, плюс ключевой хэш для поиска дублей.
- Поведение для человека не меняется: порядок, дубли, закреплённые, срок хранения, удаление на
  всех устройствах, отправка истории в группу.

## Схема

`PRAGMA user_version = 2`. Таблица `entries`:

| Колонка | Открыто | Что |
|---|---|---|
| `id` | да | `ItemId` (UUID v7), как раньше |
| `seen_ms` | да | когда запись последний раз попала в буфер, как раньше |
| `pinned` | да | как раньше |
| `hkey` | да | HMAC-SHA256 от `Content::hash()` на ключе, выведенном из ключа истории. По голому хэшу можно было бы проверять догадки («есть ли в истории `qwerty123`»), по ключевому нельзя |
| `card_nonce`, `card` | нет | карточка: всё, что нужно строке списка, поиску и служебным проверкам |
| `nonce`, `data` | нет | тело: полная запись (`Entry` в postcard), как раньше. Читается по требованию |
| `thumb_nonce`, `thumb` | нет | миниатюра, как раньше |

Индексы: `(seen_ms DESC, id DESC)` для ленты и `hkey` для дублей (не уникальный: при
совпадении берётся самая свежая строка).

Значки программ-источников вынесены в отдельную таблицу `icons(key, nonce, data)`, где `key` —
ключевой хэш пути программы. Раньше значок до 8 КБ лежал в каждой записи.

Тип записи, признак ссылки и признак файлов в открытые колонки не выносятся: по ним фильтр
работает на расшифрованных карточках.

## Карточка

Зашифрованная запись в несколько сотен байт:

- откуда: устройство, имя устройства, своя или чужая;
- тип (текст, форматированный текст, картинка, файлы, другое), ссылка ли это;
- начало текста для строки списка (400 символов) и текст для поиска: первые 8 КБ в нижнем
  регистре;
- полные размеры текста: символы, строки, байты (для подписи в строке, без чтения тела);
- формат форматированного текста (HTML или RTF);
- размеры картинки;
- для файлов — полный список `FileRef` (имена, пути, размеры, blob, p2p): он маленький и нужен
  проверкам `in_history`, `local_p2p_file` и чистке кэша;
- программа-источник: имя, путь и ключ значка.

Поиск по тексту идёт по первым 8 КБ. В очень длинном тексте совпадение дальше 8 КБ не найдётся;
это сознательная цена за то, что поиск не читает тела.

## Как работают операции

- **Лента и поиск.** Строки читаются по `seen_ms DESC, id DESC` пачками, расшифровываются
  только карточки, фильтры (закреплённые, тип, запрос) применяются к ним. Как только набрано
  `offset + limit` совпадений, чтение останавливается. Частые запросы находятся быстро, весь
  архив перебирают только редкие.
- **Добавление и дубли.** Дубль ищется по `hkey`. Совпадение поднимает существующую строку
  наверх, как раньше. Если строка с таким `id` уже есть, это тоже подъём, а не вторая запись.
- **Срок хранения.** Один `DELETE ... WHERE pinned = 0 AND seen_ms < ?` в транзакции.
- **Удаление с других устройств.** Пришедшие простые хэши переводятся в ключевые и удаляются
  по `hkey`.
- **Отправка истории в группу.** 50 последних своих записей, тела читаются только для них.
- **Счётчики.** `COUNT(*)`.
- **Чистка кэша файлов и проверки путей.** Перебор карточек файлов, без тел.

## Переход со старой базы

При первом запуске новой версии каждая строка без карточки разово получает `card` и `hkey`.
Тело (`nonce`, `data`) не перешифровывается. Переход идёт пачками по 500 строк в транзакциях:
если программа упадёт посреди, недоделанные строки догонятся при следующем запуске, а читающий
код до тех пор берёт данные из тела. Перед переходом рядом кладётся копия `history.db`.

## Настройки SQLite

`journal_mode = WAL`, `synchronous = NORMAL`, `busy_timeout = 5000` (консольный клиент и
приложение могут открыть одну базу), кэш страниц ограничен (`cache_size = -4000`, около 4 МБ),
`mmap` не включается.
