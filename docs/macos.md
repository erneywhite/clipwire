# Клиент для macOS

План этапа 4 и задание для работы на маке. Проект целиком собирается на macOS уже сейчас:
вся платформенная часть сидит за `cfg(windows)`, а на остальных ОС стоят заглушки. Задача
этапа — заменить заглушки настоящей работой с macOS, не сломав Windows.

## Состояние на старте (проверено на M1 Pro, macOS 27.2)

- `cargo build --workspace --all-targets`, `npm run build` и clippy с `-D warnings` проходят.
- `cargo test --workspace`: 312 прошли. Падает то один, то другой сетевой тест сервера с
  «Too many open files (os error 24)»: у macOS лимит 256 открытых файлов на процесс, а
  параллельные тесты поднимают десятки iroh-эндпоинтов. По одному всё проходит. Перед
  тестами — `ulimit -n 10240`, то же в CI для macOS. **Сделано:** записано в README и в п. 7.
- `rekey_moves_group_to_new_key` (сервер, `tests/devices.rs`) под нагрузкой иногда
  получает «слишком много соединений» вместо «исключено» при повторном входе R: место
  прошлого соединения освобождается позже, чем приходит отказ. Хелпер `joined()` эту гонку
  уже обходит повтором, а входы через `join_plain` в конце теста — нет. **Сделано:** все
  повторные входы идут через хелпер `joined_plain()` с тем же повтором.

## Решения

- Сборка universal (arm64 + x86_64), проверка на Apple Silicon. Минимальная версия —
  macOS 13 (Ventura).
- Без нотаризации: подписи Apple Developer нет, Gatekeeper при первом запуске ругается,
  README объясняет первый запуск (снять карантин или «Всё равно открыть»). Автообновление
  дальше работает само: Tauri качает обновление внутри программы, карантина у него нет.
- Подпись — не ad-hoc, а постоянным самоподписанным сертификатом для подписи кода
  («Clipwire Self-Signed», один на все сборки). При ad-hoc подписи требование подписи
  (designated requirement) — сам хэш кода (`cdhash H"…"`), он меняется с каждой сборкой, и
  macOS (TCC) после каждого автообновления сбрасывает «Универсальный доступ». С постоянным
  сертификатом требование — `identifier "io.github.erneywhite.clipwire" and certificate
  root = H"<хэш сертификата>"`, одинаковое у всех сборок, и разрешение переживает
  обновления. Проверено на маке (см. п. 7). Ключ сертификата терять нельзя: новый
  сертификат — новое требование, и разрешение придётся выдать заново один раз.
- Иконки в Dock нет, только значок в строке меню (`LSUIElement`, activation policy
  Accessory), как у остальных утилит буфера.
- Горячая клавиша по умолчанию Cmd+Shift+V (`CommandOrControl+Shift+V` уже так и
  работает).
- Ветка `macos`. В `main` попадает после проверки на Windows-ПК и зелёного CI на всех
  трёх ОС.

## Что сделать

Порядок важен: слежение за буфером — основа, без него остальное не проверить.

### 1. Буфер обмена (`crates/clipwire-agent/src/clipboard.rs`)

Сейчас на macOS `Watcher::start` возвращает ошибку «ещё не реализовано», запись умеет
только текст через `arboard`.

- Модуль `mac` рядом с `win`, через `objc2` / `objc2-app-kit` (`NSPasteboard`). Уведомления
  о смене буфера в macOS нет: опрос `changeCount` раз в 250 мс в отдельном потоке.
- Чтение: текст (`public.utf8-plain-text`), HTML (`public.html`) и RTF (`public.rtf`) в
  `Content::Rich`, картинки (`public.png`, иначе `public.tiff` с переводом в PNG), файлы и
  папки (`NSURL` через `readObjectsForClasses`) в `Content::Files` через `local_file_ref`
  (сейчас она только для Windows).
- Приватное содержимое не трогать: типы `org.nspasteboard.ConcealedType`,
  `org.nspasteboard.TransientType`, `org.nspasteboard.AutoGeneratedType` (ими помечают
  1Password, Bitwarden, KeePassXC и другие). Это то же, что `ExcludeClipboardContentFromMonitorProcessing` на Windows.
- Запись всех видов `Content`, включая файлы (`writeObjects` с `NSURL`) и Rich (несколько
  типов в одном элементе). Своё же копирование не считать новым: защита от петель
  (`loopguard.rs`) сравнивает содержимое, `changeCount` после записи запоминать.
- `WatchOptions` и колбэк — те же, что у Windows. Второй аргумент колбэка — exe/bundle
  программы-источника, см. п. 2.

**Состояние:** сделано в `crates/clipwire-agent/src/clipboard/mac.rs`, ждёт ручной
проверки (таблица в конце). Проверено автоматически: тесты на отдельном буфере
(`pasteboardWithUniqueName`) — текст, Rich, PNG, только TIFF, файлы и папки, приватная
метка; агент с `CLIPWIRE_HOME=/tmp/cw-test` и локальным сервером ловит текст, HTML, PNG,
файлы и папку (уходит архивом), пропускает `ConcealedType`, пишет полученное с другого
устройства и не отправляет свою запись обратно. Что выяснилось по ходу:

- Имена файлов в файловой системе macOS приходят разложенными (NFD: «й» = «и» + знак).
  В `FileRef.name` кладётся NFC (`precomposedStringWithCanonicalMapping`), путь — как есть.
- Выбор между текстом и картинкой: картинка, если рядом `public.url` (браузер «Скопировать
  изображение») или нет текста; иначе текст (таблицы кладут к тексту картинку).
- Своя запись отсекается по `changeCount`, не только через `loopguard`.
- Пока (до п. 2) программой-источником считается активная в момент опроса, вторым
  аргументом колбэка идёт путь её исполняемого файла (`…/Safari.app/Contents/MacOS/Safari`),
  поэтому имя в истории уже правильное, а иконки нет.
- `NSWorkspace.frontmostApplication` вне главного потока застывает на первом ответе —
  даже когда главный цикл событий крутится (проверено отдельной программой). Поток
  слежения не главный, поэтому активная программа берётся через `GetFrontProcess` (Carbon,
  устарел с 10.9, но работает из любого потока; помечено `shortcut:`). Владелец верхнего
  окна (`CGWindowList`) не подходит: у Finder без окон и у рабочего стола его нет.
  Для п. 2 и п. 3: то же учитывать, в Tauri можно спрашивать в главном потоке.
- Не сделано: обещанные файлы (`com.apple.pasteboard.promised-file-url`, вложения из
  Почты, фото из «Фото») — аналог виртуальных файлов Windows. `WatchOptions` на маке пока
  не используется. Отдельный пункт после п. 7, если понадобится.

Критерий: `cargo run -p clipwire-agent -- run` на маке ловит копирование текста,
форматированного текста из Safari, скриншота (Cmd+Shift+Ctrl+4) и файлов из Finder, а
вставка из истории кладёт их обратно так, что вставляется в TextEdit, Finder и браузер.

### 2. Программа-источник (`source_app.rs`)

Буфер macOS не знает, кто в него писал. Берём активную программу в момент смены
(`NSWorkspace.frontmostApplication`): имя (`localizedName`), bundle id для списка
исключений и иконку 32×32 в PNG. Исключения в настройках на маке — по bundle id или имени
(`com.agilebits.onepassword7`, `KeePassXC`).

**Состояние:** сделано, ждёт ручной проверки 2.1–2.2. Активная программа — через
`GetFrontProcess` (см. п. 1: `frontmostApplication` вне главного потока застывает).
Сведения берутся у пакета `.app` по пути исполняемого файла, а не у запущенного процесса,
поэтому работают и для закрытых программ: имя — `NSFileManager.displayNameAtPath` (как в
Finder, на языке системы), иконка — `NSWorkspace.iconForFile`, сжатая до 32×32,
bundle id — `NSBundle`. `SourceApp.exe` — имя исполняемого файла (`Safari`, `KeePassXC`),
поэтому стандартный список исключений (`KeePassXC.exe`, `1Password.exe`, `Bitwarden.exe`;
`.exe` при сравнении отбрасывается) работает и на маке. Исключение совпадает по имени
исполняемого файла, bundle id или имени пакета (`source_app::ignore_keys`); проверено
вживую с `com.apple.TextEdit`. Осталось к п. 4: подсказка в поле исключений
(`KeePass.exe`) на маке должна быть вроде `KeePassXC`.

### 3. Вставка в активное окно (`apps/desktop/src-tauri/src/popup.rs`)

- Перед показом окна запомнить активную программу (`NSRunningApplication`), после выбора
  вернуть её (`activateWithOptions`) и послать Cmd+V через `CGEvent`.
- Для синтеза нажатий нужно разрешение «Универсальный доступ» (Accessibility). Проверка
  `AXIsProcessTrustedWithOptions` при первой вставке; если разрешения нет — объяснение в
  окне и кнопка, открывающая нужный раздел настроек. Без разрешения работает «только в
  буфер».
- Окно вставки у курсора и в пределах рабочей области монитора уже кроссплатформенное,
  проверить на нескольких мониторах и со строкой меню.

**Состояние:** сделано, ждёт ручной проверки 3.1–3.4. При показе окна запоминается PID
активной программы (`GetFrontProcess`), после выбора окно прячется, программа
активируется (`activateWithOptions`), выжидается, пока она станет активной (до 0,5 с), и
посылается Cmd+V (`CGEvent`, код клавиши V — 9). Без разрешения окно вставки не
закрывается: элемент уже в буфере, плашка объясняет, как дать разрешение, кнопка
открывает раздел настроек; заодно `AXIsProcessTrustedWithOptions` с запросом добавляет
Clipwire в список (системный запрос macOS показывает один раз). Редактор картинок без
разрешения просто возвращает прежнюю программу.

Что выяснилось:
- Разрешение «Универсальный доступ» привязано к «ответственной» программе: у
  `npx tauri dev`, запущенного из терминала, это терминал. Проверять вставку — на
  собранном `.app` (`npx tauri build --debug --bundles app`, запуск через `open`).
- При ad-hoc подписи macOS узнаёт программу по хэшу кода (cdhash), а он меняется с каждой
  сборкой: после каждого обновления разрешение пришлось бы выдавать заново. Решение —
  постоянный самоподписанный сертификат, см. «Решения» и п. 7.
- shortcut: на Dvorak и других раскладках, где V не на месте QWERTY, Cmd+V по коду 9 не
  сработает; при жалобах искать код клавиши «v» в текущей раскладке (`UCKeyTranslate`).

#### Подпись сертификатом «Clipwire Self-Signed»

Сертификат делается один раз, на любом маке:

```
cat > cert.cnf <<'EOF'
[req]
distinguished_name = dn
x509_extensions = ext
prompt = no
[dn]
CN = Clipwire Self-Signed
O = Erney White
[ext]
basicConstraints = critical,CA:false
keyUsage = critical,digitalSignature
extendedKeyUsage = critical,codeSigning
EOF
openssl req -x509 -newkey rsa:2048 -nodes -keyout key.pem -out cert.pem -days 3650 -config cert.cnf
openssl pkcs12 -export -legacy -inkey key.pem -in cert.pem -name "Clipwire Self-Signed" -out clipwire-signing.p12
base64 -i clipwire-signing.p12 | pbcopy
```

`-legacy` нужен: `security import` на macOS не читает p12 с шифрованием OpenSSL 3 по
умолчанию. Можно и через «Связку ключей» → «Ассистент сертификации» → «Создать сертификат»,
тип «Подпись кода», затем экспорт в .p12. `clipwire-signing.p12` и пароль хранить вне
репозитория (менеджер паролей): это и есть «личность» программы.

Секреты репозитория для `release.yml` (заводит Erney, в коде не появляются):

| Секрет | Что |
|---|---|
| `APPLE_CERTIFICATE` | base64 от `clipwire-signing.p12` |
| `APPLE_CERTIFICATE_PASSWORD` | пароль p12 |
| `APPLE_SIGNING_IDENTITY` | `Clipwire Self-Signed` (можно не секретом, а в `env` задания) |
| `KEYCHAIN_PASSWORD` | любой случайный пароль временной связки ключей в CI |

`APPLE_ID` / `APPLE_PASSWORD` / `APPLE_API_KEY` не задаются — нотаризации нет.

Проверено на маке (временная связка ключей, рабочая не тронута): две сборки с разным
хэшем кода (`CDHash 9e34…` и `08ab…`), подписанные одним сертификатом, дают одинаковое
требование `identifier "io.github.erneywhite.clipwire" and certificate root =
H"f027…"`; у ad-hoc сборки — `cdhash H"d402…"`. `codesign --verify --deep --strict`
проходит, `spctl` отклоняет (нет нотаризации — ожидаемо). Сертификат в системе не
доверенный (`CSSMERR_TP_NOT_TRUSTED`), но `codesign -s` им подписывает. Проверить в CI,
что сборщик Tauri не требует «действительную» личность (`find-identity -v` её не видит);
если требует — подписывать собранное приложение отдельным шагом `codesign --force --deep
-s` до упаковки. Разрешение переживает смену сборки — ручная проверка 7.1 пройдена.

## Как работать на маке

- Репозиторий: `~/Documents/ClaudeCode/Clipwire`, ветка `macos`. Rust 1.100 (rustup, с
  целью `x86_64-apple-darwin`), Node 26, Command Line Tools уже стоят.
- Правила проекта — в `CLAUDE.md`: тексты для человека через `tr()` / `t()` с английским
  переводом (тесты полноты `i18n`), новая логика — с тестом, срезанные углы помечать
  `shortcut:`, сообщения коммитов по-русски, без строк Co-Authored-By.
- Не ломать Windows: всё платформенное — за `cfg(target_os = "macos")`, общий код не
  менять без нужды. После каждого шага: `cargo fmt --all`, `cargo clippy --workspace
  --all-targets -- -D warnings`, `cargo test --workspace`, `node src/lib/*.test.ts` из
  `apps/desktop`.
- Запуск приложения из исходников: `cd apps/desktop && npx tauri dev`. Настоящая сборка:
  `npx tauri build --target universal-apple-darwin`.
- Чтобы не трогать рабочие данные, для проверок — отдельная папка: `CLIPWIRE_HOME=/tmp/cw-test`.
- Всё, что требует человека у экрана (нажать горячую клавишу, выдать разрешение, вставить
  в окно, посмотреть на значок), собирать в список «ручные проверки» с точными шагами и
  ожидаемым результатом и отдавать человеку пачкой, а не по одной.
