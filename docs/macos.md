# Клиент для macOS

Как устроена поддержка macOS. Платформенный код сидит за `cfg(target_os = "macos")`,
общий код с Windows и Linux не разветвляется без нужды.

## Общие свойства

- Сборка universal (arm64 + x86_64), минимальная версия macOS 13 (Ventura).
- Иконки в Dock нет, только значок в строке меню (`LSUIElement` в `src-tauri/Info.plist` и
  `ActivationPolicy::Accessory` при запуске, для `tauri dev`).
- Горячая клавиша по умолчанию Cmd+Shift+V.
- Данные лежат в `~/Library/Application Support/Clipwire`.
- Нотаризации нет: подписи Apple Developer у проекта нет, поэтому Gatekeeper при первом
  запуске ругается. README объясняет первый запуск («Всё равно открыть» или
  `xattr -dr com.apple.quarantine`). Автообновление работает внутри программы: Tauri качает
  обновление сам, карантина у него нет.

## Буфер обмена

Реализация в `crates/clipwire-agent/src/clipboard/mac.rs` на `objc2` / `objc2-app-kit`
(`NSPasteboard`).

- Уведомления о смене буфера в macOS нет, поэтому `changeCount` опрашивается раз в 250 мс в
  отдельном потоке.
- Читаются текст (`public.utf8-plain-text`), HTML (`public.html`) и RTF (`public.rtf`) в
  `Content::Rich`, картинки (`public.png`, иначе `public.tiff` с переводом в PNG), файлы и
  папки (`NSURL` через `readObjectsForClasses`) в `Content::Files`. Папка уходит архивом.
- Выбор между текстом и картинкой: картинка, если рядом `public.url` (браузер «Скопировать
  изображение») или нет текста; иначе текст (таблицы кладут к тексту картинку).
- Имена файлов в файловой системе macOS приходят разложенными (NFD: «й» = «и» + знак). В
  `FileRef.name` кладётся NFC (`precomposedStringWithCanonicalMapping`), путь — как есть.
- Приватное содержимое не отправляется: типы `org.nspasteboard.ConcealedType`,
  `org.nspasteboard.TransientType`, `org.nspasteboard.AutoGeneratedType` (ими помечают
  1Password, Bitwarden, KeePassXC и другие). Это то же, что
  `ExcludeClipboardContentFromMonitorProcessing` на Windows.
- Запись поддерживает все виды `Content`: файлы (`writeObjects` с `NSURL`) и Rich (несколько
  типов в одном элементе). Своя запись не считается новым копированием: помимо `loopguard.rs`
  запоминается `changeCount` после записи.
- Не поддерживаются обещанные файлы (`com.apple.pasteboard.promised-file-url`: вложения из
  Почты, фото из «Фото»). `WatchOptions` на macOS не используется.

Автоматические проверки: тесты на отдельном буфере (`pasteboardWithUniqueName`) для текста,
Rich, PNG, только TIFF, файлов и папок, приватной метки.

## Программа-источник

Буфер macOS не знает, кто в него писал, поэтому источником считается программа, активная в
момент смены (`source_app.rs`).

- Активная программа берётся через `GetFrontProcess` (Carbon, устарел с 10.9, но работает из
  любого потока). `NSWorkspace.frontmostApplication` вне главного потока застывает на первом
  ответе, а поток слежения не главный. Владелец верхнего окна (`CGWindowList`) не подходит:
  у Finder без окон и у рабочего стола его нет.
- Сведения берутся у пакета `.app` по пути исполняемого файла, поэтому работают и для
  закрытых программ: имя — `NSFileManager.displayNameAtPath` (как в Finder, на языке
  системы), иконка — `NSWorkspace.iconForFile`, сжатая до 32×32, bundle id — `NSBundle`.
- `SourceApp.exe` — имя исполняемого файла (`Safari`, `KeePassXC`). Исключение совпадает по
  имени исполняемого файла, bundle id или имени пакета (`source_app::ignore_keys`); `.exe` и
  `.app` при сравнении отбрасываются, поэтому список по умолчанию с именами Windows
  (`KeePass.exe`, `1Password.exe`, `Bitwarden.exe`) тоже работает.
- Список исключений по умолчанию на macOS: `KeePassXC`, `1Password`, `Bitwarden`; у уже
  созданных настроек остаётся прежний. Подсказка в поле — `KeePassXC`; можно указать и
  bundle id (`com.apple.TextEdit`).

## Вставка в активное окно

Код в `apps/desktop/src-tauri/src/popup.rs`.

- При показе окна запоминается PID активной программы (`GetFrontProcess`). После выбора окно
  прячется, программа активируется (`activateWithOptions`), выжидается, пока она станет
  активной (до 0,5 с), и посылается Cmd+V через `CGEvent` (код клавиши V — 9).
- Для синтеза нажатий нужно разрешение «Универсальный доступ» (Accessibility). При первой
  вставке проверяется `AXIsProcessTrustedWithOptions` с запросом: Clipwire попадает в список,
  системный запрос macOS показывается один раз. Без разрешения окно вставки не закрывается:
  элемент уже лежит в буфере, плашка объясняет, как дать разрешение, кнопка открывает нужный
  раздел настроек, а Cmd+V можно нажать самому. Редактор картинок без разрешения просто
  возвращает прежнюю программу.
- Разрешение привязано к «ответственной» программе: у `npx tauri dev`, запущенного из
  терминала, это терминал, поэтому вставку проверяют на собранном `.app`.
- Ограничение: на Dvorak и других раскладках, где V не на месте QWERTY, Cmd+V по коду 9 не
  сработает (`shortcut:` в коде).
- Окно вставки у курсора и в пределах рабочей области монитора общее для всех ОС.

## Оболочка Tauri

- Меню «Правка» (Cmd+C/V/X/A/Z): у Tauri 2 на macOS меню приложения по умолчанию есть
  (`enable_macos_default_menu`). Без Dock оно не видно, но сочетания работают в полях ввода.
- Значок в строке меню — шаблонные иконки `icons/tray/mac-{on,dim,off}.png` (рисует
  `scripts/icons.mjs` из того же знака), macOS красит их под тему. Обычный значок; приглушённый
  провод — подключение, пауза и кадр пульсации обновления; перечёркнутый — нет связи. Меню
  открывается обычным кликом.
- Заголовок: `tauri.macos.conf.json` включает у окон настроек и редактора системную рамку с
  `titleBarStyle: Overlay`, `hiddenTitle` и «светофором» поверх своей полосы
  (`trafficLightPosition` 14×18). `TitleBar.svelte` на macOS не рисует свои кнопки и оставляет
  слева 92 px. Tauri заменяет массив окон целиком, поэтому в этом файле лежит копия окон;
  тест `config_tests` следит, чтобы она не разошлась с `tauri.conf.json`. Там же
  `bundle.targets` (app, dmg) и `minimumSystemVersion` 13.0.
- Подписи клавиш (`src/lib/platform.ts`): `keys()` на macOS переводит «Ctrl+P» в «⌘P», «Alt» в
  «⌥», «Shift» в «⇧»; применяется в `t()` и к подписям в `<kbd>`. Удаление записи в окне
  вставки — ⌘⌫ (клавиша «delete» на маковской клавиатуре — это Backspace, и простой ⌫ в
  пустом поиске удалял бы записи случайно).
- Скрытие окон при демонстрации экрана — `set_content_protected` Tauri, на macOS это
  `NSWindow.sharingType = none`.
- Автозапуск — `tauri-plugin-autostart` (LaunchAgent).

## Секреты

Один случайный ключ Clipwire лежит в связке ключей (generic password, служба
`io.github.erneywhite.clipwire`, учётка `state-key`). Файлы `state.bin`, `history.key` и
настройки хранилища группы лежат на диске, но зашифрованы этим ключом (XChaCha20-Poly1305,
файл начинается с `CWK1`). Так же устроено на Windows через DPAPI, интерфейс
`secret::protect/unprotect` общий. Старые открытые файлы при первом чтении переписываются
зашифрованными (`unprotect_file`). `history.key` пишется с правами 0600.

Шифрует только приложение из пакета `.app` (`secret::enable_keychain` при запуске).
Консольный агент, `tauri dev` и тесты пишут открыто: у каждой их сборки новая подпись, связка
спрашивала бы разрешение при каждой пересборке, а в CI она заблокирована. Зашифрованное они
читают (связка один раз спросит разрешение, «Всегда разрешать»). Пересборка с той же
подписью доступ к ключу не теряет, значит, запрос не появится и после обновлений.

Проверка самой связки — тест `keychain_roundtrip`, он выключен (`--ignored`) и запускается
руками: из сессии без доступа к связке она недоступна (`-25308`).

## Прочее

- Имя устройства по умолчанию — `SCDynamicStoreCopyComputerName` (тест сверяет со
  `scutil --get ComputerName`). У уже созданных настроек имя остаётся сохранённым.
- Звук копирования (`sound.rs`): один `NSSound` из `sounds/copy.wav`, новый звук перезапускает
  его.
- Отметка «скачано из интернета» (`blobs.rs`, `mark_from_internet`): атрибут
  `com.apple.quarantine` вида `0081;<время>;Clipwire;`, как у браузеров, на файлах,
  скачанных с других устройств, и на файлах внутри папок.
- Язык системы для режима «как в системе» (`i18n.rs`): первый из
  `NSLocale.preferredLanguages` (у программ из Finder переменных окружения нет).

## Сборка и выпуск

Запуск из исходников: `cd apps/desktop && npx tauri dev`. Боевая сборка:
`npx tauri build --target universal-apple-darwin` даёт `Clipwire_<версия>_universal.dmg`
(~29 МБ). Сборщик `.dmg` открывает образ в Finder, чтобы расставить иконки, окна мелькают.

Тесты на macOS запускаются с `ulimit -n 10240`: у системы лимит 256 открытых файлов на
процесс, а параллельные сетевые тесты поднимают десятки iroh-эндпоинтов. Без этого падает то
один, то другой с «Too many open files (os error 24)». Это записано в README и сделано в CI.

CI (`.github/workflows/ci.yml`): `macos-15` в матрице, fmt, clippy и тесты (через bash с
`ulimit -n 10240`), тесты фронтенда (`node src/lib/*.test.ts`) на всех ОС.

Выпуск (`release.yml`): задание `macos` работает параллельно с остальными, `tauri-action` с
`--target universal-apple-darwin` собирает `.dmg` и файлы обновления
(`Clipwire.app.tar.gz` + `.sig`) и подписывает постоянным самоподписанным сертификатом.
`latest.json` с `darwin-aarch64` / `darwin-x86_64` собирает из подписей задание `publish`
(`docs/updates.md`). Сертификат из секретов импортируется во временную связку (пароль —
случайный `uuidgen`). Сборщик Tauri подписывает и недоверенным сертификатом, по имени, и сам
включает hardened runtime. После сборки шаг «Проверка подписи» падает, если требование не
`certificate root` (то есть подпись ad-hoc); проверка идёт после загрузки в релиз.

Тестовая сборка `.app` для проверок, где нужен «Универсальный доступ»:

```
cd apps/desktop && npx tauri build --debug --bundles app   # ошибку про TAURI_SIGNING_PRIVATE_KEY в конце можно не смотреть: .app уже собран
scripts/macos-dev-sign.sh                                  # подписать target/debug/bundle/macos/Clipwire.app
open --env CLIPWIRE_HOME=/tmp/cw-test ../../target/debug/bundle/macos/Clipwire.app
```

`CLIPWIRE_HOME` задаёт отдельную папку данных, чтобы не трогать рабочие. Скрипт при первом
запуске создаёт сертификат «Clipwire Dev» в отдельной связке
`~/Library/Keychains/clipwire-dev.keychain-db` (пароль `clipwire-dev`, не секрет: там только
тестовый сертификат; в список поиска связок она не добавляется). Каждая подпись даёт одно и
то же требование, и разрешение выдаётся один раз. Это не сертификат выпусков: при переходе с
тестовой сборки на выпуск разрешение выдаётся заново один раз. Удалить связку:
`security delete-keychain ~/Library/Keychains/clipwire-dev.keychain-db`.

### Подпись сертификатом «Clipwire Self-Signed»

При ad-hoc подписи требование подписи (designated requirement) — сам хэш кода
(`cdhash H"…"`), он меняется с каждой сборкой, и macOS (TCC) после каждого автообновления
сбрасывает «Универсальный доступ». С постоянным сертификатом, одним на все сборки, требование
— `identifier "io.github.erneywhite.clipwire" and certificate root = H"<хэш сертификата>"`,
одинаковое у всех сборок, и разрешение переживает обновления. Ключ сертификата терять нельзя:
новый сертификат даёт новое требование, и разрешение придётся выдать заново.

Сертификат делается один раз, на любом маке:

```
cat > cert.cnf <<'EOF'
[req]
distinguished_name = dn
x509_extensions = ext
prompt = no
[dn]
CN = Clipwire Self-Signed
O = Erney White
[ext]
basicConstraints = critical,CA:false
keyUsage = critical,digitalSignature
extendedKeyUsage = critical,codeSigning
EOF
openssl req -x509 -newkey rsa:2048 -nodes -keyout key.pem -out cert.pem -days 3650 -config cert.cnf
openssl pkcs12 -export -legacy -inkey key.pem -in cert.pem -name "Clipwire Self-Signed" -out clipwire-signing.p12
base64 -i clipwire-signing.p12 | pbcopy
```

`-legacy` нужен: `security import` на macOS не читает p12 с шифрованием OpenSSL 3 по
умолчанию. Можно и через «Связку ключей» → «Ассистент сертификации» → «Создать сертификат»,
тип «Подпись кода», затем экспорт в .p12. `clipwire-signing.p12` и пароль хранить вне
репозитория (менеджер паролей): это и есть «личность» программы.

Секреты для `release.yml` лежат в окружении `release` (Settings → Environments), а не в
секретах репозитория: окружение пускает только теги `v*` и ждёт подтверждения выпуска,
поэтому workflow с другой ветки секретов не увидит. Там же `TAURI_SIGNING_PRIVATE_KEY` и
`TAURI_SIGNING_PRIVATE_KEY_PASSWORD`. Заводит владелец репозитория, в коде они не появляются:

| Секрет | Что |
|---|---|
| `APPLE_CERTIFICATE` | base64 от `clipwire-signing.p12` |
| `APPLE_CERTIFICATE_PASSWORD` | пароль p12 |
| `APPLE_SIGNING_IDENTITY` | `Clipwire Self-Signed` (можно не секретом, а в `env` задания) |

`APPLE_ID` / `APPLE_PASSWORD` / `APPLE_API_KEY` не задаются: нотаризации нет.
